# ARgentOS Project Layout

The canonical ARgentOS root is always:

`<project-root>/.argentos`

It is not configurable.

## Expected layout

After adoption:

~~~text
<project-root>/
├── AGENTS.md
└── .argentos/
    ├── AGENTS.md
    ├── features.toml
    ├── .agents/
    ├── .project/
    │   └── install.json
    └── .backup/
        ├── _AGENTS.md
        ├── _agents/
        └── _gitignore
~~~

`_gitignore` exists only when the original project `.gitignore` was displaced as part of installation.

## Ownership

### `<project-root>/AGENTS.md`

Project-facing ARgentOS adapter generated by the skill.

It is an adapter, not the protocol authority.

### `.argentos/AGENTS.md`

Installed ARgentOS protocol entry file.

It belongs to the ARgentOS installation and is managed by the installation method/update process.

### `.argentos/.agents/`

ARgentOS protocol payload.

This directory is the only location in the adopter project that represents the distributed protocol payload.

### `.argentos/.project/`

Adopter/runtime state.

It may contain persistent project state and preserved sessions.

The skill-owned `install.json` records installation method and installation metadata required for deterministic lifecycle operations. It must not contain user secrets.

The directory is never replaced merely because the protocol payload is updated.

### `.argentos/features.toml`

Adopter-local configuration.

It is not protocol payload and must be preserved across payload updates.

### `.argentos/.backup/`

Only displaced adopter artifacts belong here.

Permitted artifacts:

- `_AGENTS.md` — original project-root `AGENTS.md`;
- `_agents/` — original project-root `.agents/`;
- `_gitignore` — original project-root `.gitignore`, only when displaced.

Do not store protocol state, manifests, logs, sessions, configuration, or arbitrary generated files here. The installation manifest belongs in `.project/install.json`.

## Installation manifest

The canonical path is:

`.argentos/.project/install.json`

Required fields:

~~~json
{
  "schema_version": 1,
  "method": "submodule | git_tree | copy",
  "source_repository": "roldriel/argentos",
  "source_ref": "dist",
  "source_commit": "<observed commit>",
  "installed_version": "<observed protocol version>"
}
~~~

The implementation may add fields only when they are explicitly defined by a future contract.

The manifest is managed state. It is not user configuration.

## Backup rules

### Original root `AGENTS.md`

If present before adoption:

1. Move it to `.argentos/.backup/_AGENTS.md`.
2. Do not merge its contents with the ARgentOS adapter.
3. Record that it was displaced.
4. Uninstall may restore it only if the destination is absent.

### Original root `.agents/`

If present before adoption:

1. Move it to `.argentos/.backup/_agents/`.
2. Do not merge it with the ARgentOS payload.
3. Uninstall may restore it only if the destination is absent.

### Original root `.gitignore`

If the installation flow replaces it:

1. Move it to `.argentos/.backup/_gitignore`.
2. Preserve its bytes exactly.
3. Uninstall may restore it only if the destination is absent.

If no replacement occurs, do not create a backup copy.

## Backup conflicts

A restore operation must never overwrite an existing destination.

If a destination exists where a backed-up artifact would be restored:

- stop that restoration;
- return `BACKUP_CONFLICT`;
- report the verified state;
- do not delete or rename the conflicting destination automatically.

## Update preservation

An update must preserve:

- `.argentos/features.toml`;
- `.argentos/.project/`;
- `.argentos/.backup/`;
- the selected installation method.

An update may replace only protocol-managed content and generated ARgentOS adapter content explicitly covered by the update contract.

## Uninstall

Uninstall removes ARgentOS-managed installation artifacts and restores displaced adopter artifacts according to the selected session policy.

The uninstall implementation must not remove:

- unrelated project files;
- preserved sessions when the user chose **Keep sessions**;
- adopter configuration outside the defined ARgentOS ownership boundary.

After uninstall:

- **Keep sessions** → `UNINSTALLED_WITH_SESSIONS`;
- **Delete sessions** → `NOT_INSTALLED`.

## Path invariants

The implementation must derive all ARgentOS paths from `PROJECT_ROOT` and the canonical `.argentos` suffix.

It must not:

- search upward until a marker is found;
- use fixed `parents[n]` assumptions;
- treat `.agents/` at project root as the ARgentOS payload;
- make the ARgentOS root configurable through `features.toml`.
