# Issues

Before creating a new Issue, determine whether an existing Issue already represents the work.

Use an Issue for planned features, known bugs, substantial refactors, technical tasks, multi-step work, and backlog-tracked work.

Do not create an artificial Issue for a small direct request:

```text
Fix this typo.
Correct this validation condition.
Update this documentation sentence.
```

A broad request must be decomposed into coherent work units.

An Issue is a planning/tracking unit, not a commit.

A single Issue may produce multiple atomic commits and normally one coherent PR.

Do not combine unrelated Issues into one PR only for convenience.

Optionally use `roldriel/skills:github-issues` for GitHub Issue operations when available.
